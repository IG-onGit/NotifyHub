Features

Everything a notification app needs, nothing it does not

Built for developers who already have a server and want its alerts on their phone.

Your server, nobody else's

The app only calls the base URL you enter for each project. No Firebase, no push relay, no accounts, nothing sent to a third party.

A look for every project

Give each project a name, one of 11 bundled icons and a color. They appear on the real Android notification, so you know the source at a glance.

Background sync that sticks

A foreground service polls on your interval (default 20 s) and starts again after a reboot. A built-in shortcut asks Android for unrestricted battery use.

Tray and in-app history

Every notification is also saved in the app. Clear them one by one or all at once; entries older than 30 days are pruned automatically.

Tokens stay encrypted

Bearer tokens live in EncryptedSharedPreferences (AES-256) and are excluded from Android cloud and device-transfer backups.

Works with any backend

The contract is one GET endpoint returning JSON. Use Node, PHP, Python, Go or a serverless function: if it can return the JSON, it works.

How it works

Three steps from your backend to your pocket

The app pulls. Your server never needs to know where the phone is.

  1. Register a project

    In the app, add a name, a project key, your server's base URL, an optional API token, an icon and a color.

  2. Push to your server

    Your software writes a notification into your own storage, tagged with that project key, usually through a small POST endpoint.

  3. Get it on your phone

    NotifyHub polls GET /api/notifications, skips anything it has already seen and posts the rest as Android notifications.

Your server

One endpoint is the whole contract

Implement a single GET route and return JSON. Anything newer than since becomes a notification.

  • Dedupes on a stable id, so retries never double-notify.
  • Optional bearer token, sent as an Authorization header.
  • An empty notifications array is the normal answer.
API reference 
curl "https://your-server.example.com/api/notifications?since=0" \
  -H "Authorization: Bearer YOUR_TOKEN"
{
  "notifications": [
    {
      "id": "a-unique-stable-id",
      "projectKey": "my-web-app",
      "title": "Deploy finished",
      "message": "v2.4.1 deployed to production in 38s",
      "timestamp": 1739203200000
    }
  ]
}
FAQ

Questions people ask first

Is NotifyHub free, and does it need Firebase?

It is free and open source under the MIT License. It does not use Firebase, Google Cloud Messaging or any other third-party push service: the app only makes outbound requests to the server URLs you enter yourself.

Is it on the Play Store?

No. There is no store listing. You can download the prebuilt NotifyHub.apk from the GitHub repository and sideload it, or build the app yourself with Android Studio.

What does my server have to provide?

One endpoint: GET /api/notifications?since=<epochMillis>, returning JSON with a notifications array. How notifications get into your server's storage is up to you; a small POST endpoint is the usual pattern.

Will it keep working when the screen is off?

Background sync runs as a foreground service with a visible sync notification and restarts after a reboot. For the most reliable results, allow NotifyHub to run unrestricted in Android's battery settings; the Settings screen has a button for that.
