General

NotifyHub is a native Android app, written in Kotlin with Jetpack Compose, that polls your own server for notifications and displays them as real Android system notifications. Each registered project gets its own icon, accent color and name, all configured on the device.

It exists for developers who run their own backends and want alerts (deploys, errors, sign-ups, jobs finishing) on their phone without adopting Firebase or any other push service. The app only ever makes outbound requests to the server URLs you enter.

Why use it

  • No third party. No Firebase, no push relay, no account. Nothing is sent anywhere except your servers.
  • Per-project identity. Name, icon (11 bundled) and color (12 presets) show up on the notification itself.
  • Simple contract. One GET endpoint that returns JSON.
  • Persistent. A foreground service keeps polling, and restarts after a reboot when sync is enabled.
  • History. Notifications are also kept in the app until you clear them, and pruned after 30 days.

New here? Read How it works, then follow Installation.

How it works

How it works

NotifyHub never receives pushes. It asks your server for anything new on a timer.

  1. You register each piece of software as a project in the app: name, project key, server base URL, optional token, icon and color.
  2. Your own services store notifications on your server, tagged with the same projectKey.
  3. A foreground service calls GET /api/notifications?since=<epochMillis> for each project every poll interval (20 s by default).
  4. New items, de-duplicated by id, are saved to the local history and posted as Android notifications styled with the project's icon and color.
 your service        your server                         NotifyHub (phone)
 ------------        -----------                         -----------------
 POST /api/      ->  stores row with                     every N seconds, per project:
 notifications       server id + timestamp               GET /api/notifications?since=T
                                                         Authorization: Bearer <token>
                     <--------------------------------   200 { "notifications": [...] }
                                                         dedupe by id -> history -> system
                                                         notification (project icon + color)

Notifications are available both in the Android tray (clearable there) and in the app's own list, where you can clear them individually or all at once.

GeneralInstallation

Installation

There is no store listing. Pick one of the paths below.

Option 1: install the prebuilt APK

The repository contains NotifyHub.apk, a debug build produced by the repository's GitHub Actions workflow. Copy it to your phone and open it, allowing "install from this source" when Android asks. With USB debugging enabled you can also install it from a computer:

adb install -r NotifyHub.apk

Option 2: run from Android Studio

  1. Clone the repository and open the folder in Android Studio. Let Gradle sync (internet needed once).
  2. Enable Developer options and USB debugging on your phone (Settings, About phone, tap "Build number" 7 times).
  3. Select your phone as the target and click Run.
git clone https://github.com/IG-onGit/NotifyHub.git
cd NotifyHub

Option 3: build an APK

In Android Studio choose Build, Build App Bundle(s) / APK(s), Build APK(s), then copy app/build/outputs/apk/debug/app-debug.apk to your phone. From the command line, the repository ships the Gradle wrapper properties (Gradle 8.7) but not the wrapper binaries, so generate them once with any local Gradle install:

gradle wrapper
./gradlew assembleDebug

First launch

  1. Grant the notification permission when asked.
  2. Open Projects and register your first project. The project key must match what your server tags notifications with.
  3. Open Settings and switch Background sync on.

InstallationAPI contract

API contract

This is the only endpoint the app calls. Implement it on every server you register.

Request

GET {base}/api/notifications?since=1739203200000
Authorization: Bearer <token>
PartValue
Query sinceEpoch milliseconds. Return only items with timestamp > since (exclusive). The app sends the newest timestamp it has stored for that project, or 0 on first run or after a full clear.
Header AuthorizationBearer <token>, sent only if you set a token for the project. Validate it and answer 401 if wrong.

Response

200 OK with Content-Type: application/json:

{
  "notifications": [
    {
      "id": "a-unique-stable-id",
      "projectKey": "my-web-app",
      "title": "Deploy finished",
      "message": "v2.4.1 deployed to production in 38s",
      "timestamp": 1739203200000
    }
  ]
}

When nothing is new, return {"notifications": []} with 200. That is the normal answer on most polls; do not return an error or 204.

Field rules

FieldTypeRule
idstringUnique and stable. The app de-duplicates on it. Never reuse an id, never change it on retry.
projectKeystringMust exactly match the key registered in the app. The app polls each project separately and keeps the items tagged with that project's key.
titlestringNotification title.
messagestringNotification body.
timestampnumberEpoch milliseconds. Newer notifications must have a strictly larger value.

All five fields are required in every item. Return items oldest to newest.

Client behaviour

  • Connect and read timeouts are 15 seconds each.
  • A failed poll is logged and retried on the next cycle; the app does not show an error notification.
  • Local history older than 30 days is pruned after each cycle.
  • CORS is not needed: the client is native.
ConfigurationSending notifications

Sending notifications

The app never pushes to your server, so how notifications get into your storage is up to you. A minimal pattern is a POST /api/notifications endpoint that your services call and that appends to a table the GET reads from.

POST /api/notifications

PartValue
Header Content-Typeapplication/json
Header AuthorizationBearer <token>. The same token, or a separate write token.
BodyprojectKey, title, message (strings, required). The server assigns id and timestamp.
curl -X POST "https://your-server.example.com/api/notifications" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"projectKey":"my-web-app","title":"Deploy finished","message":"v2.4.1 deployed to production in 38s"}'

Suggested answers: 201 Created with the stored item, 400 for missing fields, 401 for a bad token.

Implementation notes

  • Server-assigned, increasing timestamps. The app resumes from the highest timestamp it has stored. If two items share a millisecond or one is written late with an older timestamp, it can be missed. Stamp at insert time and bump by 1 ms on collision.
  • since is exclusive. Use timestamp > since.
  • Retention. Keep enough history to survive the phone being offline, and make since=0 return something sensible.
  • Keep the GET cheap. It runs every poll interval; index the timestamp column.

Quick end-to-end test

# 1. Push a test notification
curl -X POST "https://your-server.example.com/api/notifications" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"projectKey":"test","title":"Hello","message":"It works"}'

# 2. Confirm the app will see it
curl "https://your-server.example.com/api/notifications?since=0" \
  -H "Authorization: Bearer YOUR_TOKEN"

# 3. Confirm auth is enforced (expect 401)
curl -i "https://your-server.example.com/api/notifications?since=0" \
  -H "Authorization: Bearer WRONG_TOKEN"

Then in the app: register a project with key test, your base URL and token, and enable Background sync. The notification should appear within one poll interval. The same guide is in NotifyHub.md in the repository.

API contractSecurity and permissions

Security and permissions

NotifyHub is designed so that your data only travels between your phone and your servers.

  • Use HTTPS for every server base URL. The token is sent as a bearer header on every request, so plain HTTP would expose it on the network.
  • Encrypted tokens. Tokens are stored with EncryptedSharedPreferences (AES-256 keys and values) and the preferences file is excluded from Android cloud backup and device transfer. Deleting a project also removes its token.
  • No third party. The only network destinations are the base URLs you register.
  • Sideloaded. There is no store distribution; you install the APK yourself.

Permissions

PermissionWhy
INTERNET, ACCESS_NETWORK_STATEReach your server.
POST_NOTIFICATIONSShow notifications (runtime prompt on Android 13 and newer).
FOREGROUND_SERVICE, FOREGROUND_SERVICE_DATA_SYNCRun the polling service.

System requirements

Running the app

ItemRequirement
Android8.0 (API 26) or newer
PermissionNotifications (you are asked on Android 13 and newer)
NetworkInternet access to the server you register
RecommendedBattery optimization set to unrestricted for reliable background sync

On your server

  • A GET /api/notifications?since= endpoint that returns the JSON described in the API contract.
  • HTTPS, and token validation if you use a token.
  • Optionally a POST endpoint so your services can add notifications.

Building from source

  • Android Studio, with internet access on first sync to download dependencies.
  • JDK 17 and Gradle 8.7 (Android Gradle Plugin 8.5.2, Kotlin 1.9.24).
  • Android SDK platform 34 (compileSdk and targetSdk 34, minSdk 26).
